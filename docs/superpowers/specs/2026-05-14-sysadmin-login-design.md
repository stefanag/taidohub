# Sysadmin Login — Design

**Date:** 2026-05-14
**Goal:** Make the existing `/login` page usable by adding the missing pieces — a `role` field on the user record, a seeded sysadmin account, and the better-auth glue that connects them.

---

## Context

The scaffold already ships most of the auth surface:

- `apps/frontend/src/app/router/routes/login.tsx` — `/login` route wrapping `LoginForm` in a Card layout, navigates to `/posts` on success.
- `apps/frontend/src/features/auth-by-email/` — `LoginForm`, `SignupForm`, `auth.api.ts` with a better-auth React client pointed at `VITE_API_URL`.
- `apps/backend/src/infrastructure/auth/better-auth.ts` — better-auth Node config wired to the Drizzle adapter and `user / session / account / verification` tables.
- `apps/frontend/src/shared/lib/casl/defineAbilityFor.ts` and `apps/backend/src/modules/{posts,users}/*.abilities.ts` — CASL already special-cases `user.role === 'admin'` for `can('manage', 'all')`.

What's missing: the `user` table has no `role` column, no admin row exists, and better-auth doesn't know to surface a role on `session.user`. The CASL admin branch is reachable code but it never fires today.

## Architecture

Five small, ordered changes — each independently committable.

### 1. Schema: add `role` to the `user` table

`apps/backend/src/infrastructure/database/schema/users.ts`:

```ts
export const user = pgTable('user', {
  // ...existing columns
  role: text('role').notNull().default('user'),
});
```

Migration is generated by `pnpm --filter backend run db:generate` and committed alongside the schema change.

**Why `not null default 'user'`** — every user gets a role; the default means we never have to special-case `null` in either the guard or CASL. The value is a plain `text` (no enum) because better-auth doesn't need it constrained and we want to keep migrations cheap.

### 2. better-auth integration

`apps/backend/src/infrastructure/auth/better-auth.ts` — add to the config object:

```ts
user: {
  additionalFields: {
    role: {
      type: 'string',
      defaultValue: 'user',
      required: false,
      input: false,
    },
  },
},
```

- `type: 'string'` — matches the `text` column.
- `defaultValue: 'user'` — better-auth populates this on signup if no value is supplied.
- `input: false` — strips `role` from the signup payload so a sign-up request can't escalate privileges. Only the seed script (which bypasses the signup endpoint by writing directly to the column) and an explicit admin tool can set it.

The `apps/backend/src/infrastructure/auth/auth.guard.ts` cast (`role: (session.user as { role?: string | null }).role ?? null`) already expects this field. No guard change needed.

### 3. Env schema

`apps/backend/src/config/env.schema.ts` — add:

```ts
SYSADMIN_EMAIL: z.string().email().default('sysadmin@example.com'),
SYSADMIN_PASSWORD: z.string().min(8).default('sysadmin'),
```

Defaults pass validation; dev works out of the box with no `.env` edits.

`apps/backend/.env.example` — append the two keys with the defaults, plus a one-line comment that they're consumed only by the seed script.

### 4. Seed script

`apps/backend/src/scripts/seed.ts` — new file. Invoked via:

```bash
pnpm --filter backend run db:seed
```

The script:

1. Parses `process.env` through `EnvSchema` (same way `db:migrate` does).
2. Opens a Drizzle client via `createDrizzleClient(env.DATABASE_URL)`.
3. Looks up the existing row: `db.select().from(user).where(eq(user.email, env.SYSADMIN_EMAIL)).limit(1)`.
4. **If the row exists**: ensures `role === 'admin'`; if not, updates it. Then exits.
5. **If the row doesn't exist**: calls better-auth's server-side sign-up to create the user with a properly-hashed password, then issues a single `UPDATE user SET role = 'admin' WHERE email = …` to set the role (avoiding the `input: false` restriction by going directly to the column).
6. Logs `[seed] sysadmin: <email> (role=admin)` on success and exits 0.

Idempotent — re-running on a populated DB is safe and a no-op.

`apps/backend/package.json` — add the script entry:

```json
"db:seed": "tsx src/scripts/seed.ts"
```

### 5. Frontend: a11y fix on `FormMessage` (test-fix path)

`apps/frontend/src/shared/ui/form.tsx` — when `FormMessage` renders an error message, add `role="alert"` to the `<p>`. Currently:

```tsx
<p className={cn('text-sm font-medium text-destructive', className)} {...props}>
  {body}
</p>
```

Becomes:

```tsx
<p
  role="alert"
  className={cn('text-sm font-medium text-destructive', className)}
  {...props}
>
  {body}
</p>
```

This makes screen readers announce validation messages on form submit failure (a real a11y improvement) and incidentally unblocks the buggy existing test that queries `getAllByRole('alert', { hidden: true })`.

## Data flow

**Signup (unchanged for normal users):**

1. SignupForm → `POST /api/auth/sign-up/email`
2. better-auth creates `user` row with `role = 'user'` (the column default; `input: false` strips any role value from the payload)
3. Auto-sign-in returns a session cookie; subsequent `auth.guard` reads pick up `session.user.role` and stamp `req.user.role`; CASL falls through to authenticated-non-admin rules.

**Login (existing):**

1. LoginForm → `POST /api/auth/sign-in/email`
2. better-auth verifies password, issues session cookie.
3. Frontend navigates to `/posts`; subsequent API calls carry the cookie.

**Sysadmin (new):**

1. Developer runs `pnpm --filter backend run db:seed` (typically once after first migration).
2. Script ensures the sysadmin row exists with `role = 'admin'`.
3. Developer signs in via `/login` with the env-configured email/password (defaults: `sysadmin@example.com` / `sysadmin`).
4. `session.user.role === 'admin'` → CASL `manage all` → every action on every subject.

## Error handling

| Failure | Behavior |
|---|---|
| Seed: DB unreachable | Print `[seed] failed: DATABASE_URL is unreachable (<original error>)` and exit 1. |
| Seed: better-auth sign-up rejects (e.g. weak password) | Re-throw with `[seed] failed:` prefix; exit 1. The dev default `sysadmin` is 8 chars so this path is theoretical for the defaults. |
| Seed: role-update query fails | Surface the DB error verbatim; exit 1. |
| `env.SYSADMIN_PASSWORD` < 8 chars | Zod validation fails at the script's `EnvSchema.parse(process.env)` step — same handling as any other env misconfiguration today. |
| Login with unknown email | better-auth returns its existing error envelope; `LoginForm`'s `submitError` state surfaces it. No new path. |

## Out of scope

- Better-auth's admin plugin (ban/impersonate/list-users) — overkill for a single seeded admin.
- Multiple admin emails or a role hierarchy beyond `'user'`/`'admin'`.
- UI affordances for admin (admin badge, admin menu) — covered by existing `<Can>` checks.
- `auth.guard` unit/integration tests — pre-existing untested code, separate concern.
- Production credential rotation — the seed script uses env vars, so rotation is just a re-run with new env.
