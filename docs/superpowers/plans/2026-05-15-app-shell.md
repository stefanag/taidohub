# App Shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the frontend into two layouts via TanStack Router pathless layout routes — a public layout (`_public`) for anonymous-facing pages and an auth-gated app shell (`_app`) for the logged-in experience that renders the shadcn sidebar on the left and route content on the right. Centralise the auth `beforeLoad` on `_app`; redirect authenticated users from `/` to `/dashboard`; redirect anonymous users from any `_app` route to `/login`.

**Architecture:** Two new pathless-layout route files (`_public.tsx`, `_app.tsx`) become parents of the existing route files. `__root.tsx` shrinks to a bare `<Outlet />` + devtools. The placeholder `AppSidebar` gets a real implementation with two nav entries plus a footer carrying the locale switcher and sign-out. A single `APP_LANDING_ROUTE` constant feeds both the home-redirect and `LoginPage`'s post-login navigation. Header drops its signed-in branch (dead code once authed users live in `_app`).

**Tech Stack:** TanStack Router 1.x (pathless layout routes via leading-underscore `id`), shadcn sidebar primitives (already in `apps/frontend/src/shared/ui/sidebar.tsx`), React 19, Vitest 4, react-i18next 17, better-auth 1.6.

- [ ] **Step 1: Write the layout file**

```tsx
import { createRoute, Outlet, useRouterState } from '@tanstack/react-router';
import * as React from 'react';

import { Header } from '@/widgets/header';

import { rootRoute } from './__root.js';

/**
 * Public-facing layout. Used for anonymous pages: `/`, `/login`, and any
 * future marketing route. Renders the global `Header` except on auth pages
 * (`/login`, `/signup`) — those carry their own hero chrome.
 */
function PublicLayout(): React.ReactElement {
  const pathname = useRouterState({ select: (s) => s.location.pathname });
  const isAuthPage = pathname === '/login' || pathname === '/signup';
  return (
    <>
      {isAuthPage ? null : <Header />}
      <Outlet />
    </>
  );
}

export const publicLayoutRoute = createRoute({
  getParentRoute: () => rootRoute,
  id: '_public',
  component: PublicLayout,
});

export const Route = publicLayoutRoute;
```

The `id: '_public'` (leading underscore, no `path:`) is the TanStack Router signal for "pathless layout route" — it contributes no URL segment.

- [ ] **Step 3: Implement the layout**

Create `apps/frontend/src/app/router/routes/_app.tsx`:

```tsx
import { createRoute, Outlet, redirect } from '@tanstack/react-router';
import * as React from 'react';

import { authClient } from '@/features/auth-by-email';
import {
  Sidebar,
  SidebarProvider,
  SidebarTrigger,
} from '@/shared/ui/sidebar';
import { AppSidebar } from '@/widgets/appsidebar/ui/AppSidebar';

import { rootRoute } from './__root.js';

/**
 * Auth-gated layout. Every route under this parent runs through the
 * `beforeLoad` check below and renders inside the shadcn sidebar shell.
 *
 * Layout: `<AppSidebar>` (left, persistent on desktop, Sheet on mobile)
 * +  main area carrying a mobile-only `<SidebarTrigger>` floating in the
 * top-left corner.
 */
function AppLayout(): React.ReactElement {
  return (
    <SidebarProvider>
      <AppSidebar />
      <main className="min-h-svh flex-1">
        <div className="sticky top-2 left-2 z-10 w-fit md:hidden">
          <SidebarTrigger />
        </div>
        <Outlet />
      </main>
    </SidebarProvider>
  );
}

export const appLayoutRoute = createRoute({
  getParentRoute: () => rootRoute,
  id: '_app',
  beforeLoad: async () => {
    let hasSession = false;
    try {
      const result = await authClient.getSession();
      hasSession = Boolean(result.data);
    } catch {
      // Network/server failure: treat as no session so the user lands on /login
      // rather than a blank error screen.
      hasSession = false;
    }
    if (!hasSession) {
      throw redirect({ to: '/login' });
    }
  },
  component: AppLayout,
});

export const Route = appLayoutRoute;
```

## Rollback strategy

Each task is its own commit. To roll back a single task: `git revert <sha>`. The route-tree regeneration in Task 7 is reversible — `routeTree.gen.ts` is generated, so any `git revert` followed by `pnpm --filter frontend exec vite build` will rebuild it correctly.

If Task 5 (`__root.tsx` strip) is reverted, the Header allowlist comes back but the new `_public.tsx` layout still exists and is unused — that's harmless dead code, not a runtime break.

## Notes & gotchas

- **TanStack Router proxy-spy.** `vi.spyOn(authApi.authClient, 'getSession')` may fail because `authClient` is a better-auth Proxy. The `_app` and `index` route tests include a fallback module-mock pattern in their Step 1 notes — use it if you hit `Cannot redefine property` or similar.
- **`routeTree.gen.ts` is auto-generated.** Don't hand-edit it. Run `vite build` (or `vite dev`) after adding/removing route files; the plugin rewrites the file.
- **Sidebar mobile mode.** shadcn `<Sidebar>` auto-switches to a `Sheet` overlay below a configurable breakpoint (default `md`). The floating `<SidebarTrigger />` in `_app.tsx` is `md:hidden` so it only appears on mobile.
- **Order of test files matters when proxy-spy is in play.** If one test file mocks `authClient` and another doesn't reset its mock, leakage causes flakey passes. The `afterEach(() => vi.restoreAllMocks())` in every new test file guards against this.
- **`APP_LANDING_ROUTE` is a TanStack Router `to` value.** It must match a registered route's path exactly. If you ever rename `/dashboard`, update the constant — TanStack's typed routes will surface a build error if it gets out of sync.
- **The Japanese motto on `/login`** stays as a literal — not translated, not localized. Preserve it.
